# План: калибровка выходов по траекториям сигналов

> **Математическая модель: разделимость популяций траекторий + малопараметрические кривые порогов, калиброванные касательным реплеем.**
>
> Каждая позиция — случайный путь нетто-PnL длиной 1440 минут. Модель не предсказывает цену и не ищет параметры перебором по прибыли — она опирается на РАЗНИЦУ между двумя популяциями траекторий: победители (пришли в плюс к 24ч) и проигравшие. У них по-разному устроены бегущий минимум MAE(t), бегущий максимум MFE(t) и мгновенное pnl(t); пока эти распределения статистически различимы, существуют пороги, по одну сторону которых текущий путь выглядит как победитель, по другую — как проигравший. Первый шаг конвейера — проверить саму различимость; без неё калибровать нечего.
>
> Пороги задаются монотонными семьями кривых с 1–2 свободными параметрами, а параметры калибруются **касательным реплеем до целевой ПУТЕВОЙ вероятности ошибки**: «эта кривая убивает ≤5% победителей за весь путь позиции». Ручка каждого механизма — явная цена ошибки первого рода на уровне пути, а не поминутный квантиль. Поминутные квантили используются только как инициализация формы: во-первых, позиция живёт 1440 минут, и объединение поминутных событий даёт совсем другую путевую вероятность, чем квантиль одной минуты; во-вторых, для порогов по касанию квантиль бегущего минимума вообще непригоден как значение порога (разобрано в 4.2).
>
> Переобучение контролируется структурно: у семьи кривых физически нет ёмкости запомнить шум выборки; нестационарность рынка — стратификацией по режимам (только там, где хватает данных) с жёстким фолбэком на глобальный фит; честность оценки — реплеем с bootstrap-доверительными интервалами и walk-forward на месяцах, которых кривые не видели. Деньги модель зарабатывает не предсказанием, а асимметрией: механизмы только закрывают позиции, поэтому худший случай ограничен бейзлайном «держать 24 часа», а выигрыш — отрезанные хвосты трупов и зафиксированные пики при сохранённых траекториях победителей.
>
> **Чем это отличается от простого исполнения торговой рекомендации.** Буквальный исполнитель берёт из поста всё: вход, цели, стоп, плечо — и его результат равен качеству манименеджмента автора, который у сигнальных каналов обычно и есть слабое место (плечи X13–25 при стопе в несколько процентов — слив на дистанции при любом разумном винрейте). Эта модель берёт у автора только то, в чём его эдж измеримо подтверждён, — направление и момент входа, — а всё сопровождение заменяет на выходы, откалиброванные по фактическому поведению его же сигналов. Рекомендация статична и локальна: один пост — один набор цифр, написанных до того, как рынок ответил; наши пороги — функции возраста позиции, оценённые по ансамблю всех сигналов канала. Отсюда разрез ответственности: парсинг и исполнение — наши, качество рекомендаций — автора; его цифры мы не «улучшаем» и не фильтруем — мы либо монетизируем измеренный профиль его эджа, либо (если профиль убыточен) меняем автора.

Самодостаточное руководство. Конвейер:

1. **Go/no-go**: проверка разделимости популяций по дампу.
2. **`main.test.ts` — сборщик траекторий**: каждый сигнал открывает позицию, которую ничто не закрывает 24 часа; движок пишет поминутный НЕТТО pnl в дамп.
3. **Калибровка**: семьи кривых + касательный реплей → сгенерированные сетки уровней.
4. **`main.strategy.ts` — исполнение**: сетки в `Level`, проверки в `listenActivePing`.

**Сквозной инвариант: все пороги на всех этапах — в нетто-процентах pnl**, ровно той величине, что лежит в `data.pnl` дампа и в `data.pnl.pnlPercentage` внутри `listenActivePing`. Издержки (~0.4% за круг у ccxt binance spot) уже внутри: на первом тике позиции pnl ≈ −0.4% при цене, равной цене входа. Ничего не пересчитывать от цен — калибровка и исполнение обязаны жить в одной системе координат.

**Карта ролей механизмов** (каждый на своей территории, конкуренция за сделки запрещена):

| Механизм | Роль | Территория |
|---|---|---|
| Hard stop (4.1) | КАТАСТРОФА — невыживаемый хвост | в нормальной жизни не срабатывает никогда |
| Пол по минутам (4.2) | рядовые ЛОСИ + анти-лимб снизу | pnl < 0 |
| Profit lock (4.3) | рядовая ДОХОДНОСТЬ + анти-лимб сверху | pnl > 0, пик ниже arm трейлинг-тейка |
| Trailing take (4.4) | ВЫСТРЕЛЫ pnl | пик ≥ arm, единицы траекторий на ансамбль |
| `minuteEstimatedTime` | терминальный выход | всё, что не разрешилось за 24ч |

## 1. Go/no-go: разделимость популяций (первый скрипт, до любой калибровки)

Вся модель стоит на различимости распределений победителей и проигравших. Прежде чем строить кривые:

1. Собрать по дампу (раздел 3) ряды `mae_i(t)`, `mfe_i(t)`, `pnl_i(t)`, разметить исходы.
2. На сетке контрольных минут (например, 30, 60, 120, 240, 480, 720, 1080, 1439) посчитать KS-дистанцию распределений победителей против проигравших — отдельно по MAE(t), MFE(t), pnl(t).
3. **No-go**: если разделение отсутствует или появляется только к финалу — у канала нет пригодного для сопровождения профиля, конвейер останавливается (канал торгуется бейзлайном или выбывает).
4. Побочный продукт — **минута армирования profit lock**, по формальному правилу компилятора (сетку руками не трогаем, значит и это число обязано вычисляться): первая контрольная минута, с которой KS-статистика по MFE превышает критическое значение уровня значимости α на k контрольных минутах подряд. α и k — константы процедуры (например, α = 0.05, k = 3), фиксируются в паспорте калибровки; порог KS при этом — функция α и размеров выборок (стандартное критическое значение), не ручное число.

Скрипт дешёвый (один проход по дампу), результат — таблица KS по минутам, уходит в паспорт калибровки.

## 2. Тест-файл: сборщик траекторий

Позиция должна прожить ровно 24 часа нетронутой, чтобы дамп записал полную траекторию. Убираются ВСЕ способы закрытия, кроме времени.

### Недостижимые TP/SL

```typescript
import { addStrategySchema, Cache, Position, setConfig } from "backtest-kit";

setConfig({
  CC_MAX_STOPLOSS_DISTANCE_PERCENT: 100, // иначе валидатор не пропустит стоп -50%
});

const NEVER_STOP_PERCENT = 50;
```

Во входе:

```typescript
return {
  id: `${entry.id}-${entry.symbol.toLowerCase()}`,
  symbol: entry.symbol,
  ...Position.moonbag({
    position: entry.position,
    currentPrice,
    percentStopLoss: NEVER_STOP_PERCENT, // стоп -50% — практически недостижим
  }),                                    // тейк у moonbag фиксированный +50% — тоже недостижим
  note: JSON.stringify(info, null, 2),   // фото из message обязательно omit(message, "photo")
  minuteEstimatedTime: 24 * 60,          // единственный выход: ровно 1440 минут
};
```

- `Position.moonbag` возвращает `{ position, priceTakeProfit, priceStopLoss }`: тейк +50% от текущей цены, стоп — заданный процент. Оба на ±50% за сутки почти никогда не достигаются — позиция доживает до временного выхода.
- `minuteEstimatedTime: 24 * 60` — принудительное закрытие через 24 часа: ровно 1440 поминутных точек на сигнал («24 часа свечей» в виде `active`-тиков дампа).
- **Никаких `listenActivePing` / `commit*` в тест-файле** — ничто не вмешивается в траекторию.

### Вход — продовым пайплайном

Траектория должна стартовать от того момента, где войдёт прод, иначе кривые опишут другой процесс:

- тот же `Cache.file` (интервал 5m, имя кеша прода — закешированные ответы LLM переиспользуются бесплатно);
- то же окно скрейпа и гейт свежести (`when - message.date > FRESH_WINDOW_MINUTES → null`);
- гейты качества (минимум целей и т.п.) можно снять — соберутся траектории всех сигналов, фильтры прода накладываются оффлайн по `note`.

### Свойства метода (знать, не чинить)

- Пока позиция активна, новые сигналы той же монеты не открываются — перекрывающиеся сигналы одной монеты траекторий не дают.
- Ход −50% за сутки обрежет траекторию стопом. Такие траектории — зафиксированные катастрофы: **исключаются из фита кривых, но ОБЯЗАТЕЛЬНО остаются в реплее обоих плеч** (4.5) — выкинуть их из оценки значит посчитать дельту механизмов на выборке без их главного выигрыша, а бейзлайн «держать 24ч» завысить.
- `active`-тики каждую минуту на все символы: дамп за месяц — десятки МБ, читать потоково.

Запуск: `npm start -- --backtest --ui --entry <путь к main.test.ts> --cache`.

## 3. Что лежит в дампе (`dump/report/backtest.jsonl`)

Одна строка = одно событие, всё нужное — в `data`:

- **`action: "opened"`** — вход: `signalId`, `position`, `priceOpen`, `openTime` (ms), `note` (внутри `entry` с целями/стопом автора — для оффлайн-фильтров).
- **`action: "active"`** — поминутный снапшот (проверено: ровно раз в 60с, без дыр):
  - `timestamp` (ms) → минута траектории: `t = (timestamp - openTime) / 60000`;
  - `pnl` — **нетто**-процент, направленный (у шорта знак уже учтён);
  - `peakProfitPercentage` — бегущий максимум нетто pnl = **MFE(t)**;
  - `maxDrawdownPercentage` — бегущий минимум нетто pnl = **MAE(t)**;
  - движок считает MFE/MAE сам — running min/max строить не нужно.
- **`action: "closed"`** — финал: `pnl` (итог на 1440-й минуте), `duration`, `closeReason`, финальные peak/drawdown.

Экстремумы — по минутным тикам, без игл внутри свечи. Это корректно: исполнять пороги будет `listenActivePing`, который видит те же минутные цены — калибровка описывает ровно наблюдаемый им процесс. Допущение, фиксируемое в паспорте калибровки: **закрытие по цене минуты наблюдения**; в live `commitClosePending` исполнится с задержкой и проскальзыванием — известный зазор между бэктестом и живым исполнением.

## 4. Калибровка уровней

### Единый принцип

Два математических факта определяют схему калибровки:

1. **Квантиль бегущего минимума не может подниматься.** `mae_i(t)` — running min, невозрастающий у каждой траектории; поточечный квантиль семейства невозрастающих функций сам невозрастающий. Поэтому «растущий к безубытку пол», посчитанный как поминутный квантиль MAE(t), невозможен: такая кривая может только углубляться, а фит неубывающей кривой на невозрастающие данные вырождается в константу. Расти пол может только как кривая, заданная семьёй по построению и откалиброванная внешней целью (реплеем), — интуиция «поздние глубокие заходы — свойство трупов» относится к новым заходам, которые running min не выражает: он помнит ранний провал победителя навсегда.
2. **Поминутный квантиль ≠ путевая вероятность.** Даже корректный q05 на каждой отдельной минуте не означает «5% победителей убито за путь»: позиция прикасается к кривой 1440 раз, объединение событий даёт долю заметно выше. Семантика «цена ошибки первого рода» живёт на уровне ПУТИ — значит, и калибровать надо путевую величину.

Отсюда единая схема для всех кривых:

```
форма:         монотонная семья с 1–2 свободными параметрами
               (пол:  floor(t) = a − b·e^(−t/τ), якорь floor(0) = hardStop;
                лок:  lock(t)  = c·(1 − e^(−t/κ)), действует с минуты армирования)
инициализация: эмпирические поминутные квантили (q05 MAE / q25 MFE) — ТОЛЬКО форма, не значения
калибровка:    касательный реплей по траекториям — свободный параметр подбирается до
               ЦЕЛЕВОЙ ПУТЕВОЙ доли убитых победителей (это и есть ручка механизма)
проверка:      bootstrap-CI дельты против бейзлайна «держать 24ч» (4.5)
```

Касательный реплей — симуляция минута за минутой: позиция закрывается при первом касании кривой, ровно как её закроет листенер. Один и тот же инструмент служит калибровке (внутренний цикл подбора параметра) и оценке (внешний, на отложенных месяцах); семантика касания — «победитель, нырнувший под кривую и вернувшийся, в реальности был бы уже закрыт» — соблюдена по построению.

### Подготовка данных

1. Потоковый проход дампа: `active` группируются по `signalId` в ряды `pnl[t]`, `mfe[t]`, `mae[t]` (t — целые минуты 0..1439); `closed` даёт `finalPnl`.
2. Разметка: **победитель** = `finalPnl > 0` (нетто). Чувствительность порога проверить отдельно (0 против +0.5%): около нуля живут «+0.1%-победители», размывающие MFE-статистики лока.
3. Траектории, обрезанные стопом −50% или краем фрейма: из ФИТА исключаются, в РЕПЛЕЕ обоих плеч участвуют обязательно (катастрофы — главный выигрыш hard stop), помечаются флагом.

### 4.1 Hard stop

**Роль: ловить КАТАСТРОФУ** — не управлять позицией, а ограничить невыживаемый хвост (делистинговый слив, каскад ликвидаций, новостной обвал). В нормальной жизни позиции не срабатывает никогда; сработка — событие для разбора (катастрофа реальна либо калибровка пола отстала от режима), а не «механизм отработал».

- Одна константа. Инициализация — q95–q99 финального MAE победителей; итоговое значение — из касательного реплея с целевой путевой долей убитых победителей ≪1%.
- **Только глобальный** (весь год данных): хвостовая статистика на пуле режима в 25–40 победителей — это 1–2 порядковых наблюдения, по ним хвост не оценивается.
- Якорь пола: `floor(0) = hardStop`.
- Биржевой стоп `Position.moonbag` в проде ставится глубже hard stop на запас (издержки + гэп, ~1–1.5пп): страховка на случай отставания процесса, не рабочий механизм — иначе гросс-цена сработки биржевого стопа разойдётся с нетто-порогом калибровки.

### 4.2 Пол по минутам

**Роль: рядовые ЛОСИ + нижняя губа анти-лимба** — позиция в минусе не пересиживает сужающийся допуск: смерть от стагнации наступает по возрасту, не по цене.

- Семья `floor(t) = a − b·e^(−t/τ)`: монотонный подъём от `floor(0) = hardStop` к позднему уровню `a` (окрестность −1%, определяется калибровкой). Подъём — свойство семьи; данные (через реплей) решают только, насколько быстро и до какого уровня.
- Калибровка: при зафиксированном якоре свободные параметры подбираются касательным реплеем до целевой путевой доли убитых победителей (~5%; величина — ручка владельца).
- Режимные варианты допустимы: пол опирается на центральную часть распределения, где режимных n хватает (процедура допуска — раздел 6).

### 4.3 Profit lock

**Роль: рядовая ДОХОДНОСТЬ + верхняя губа анти-лимба.** Собирает типичный заработок обычных победителей (единицы процентов), который без лока испаряется при позднем развороте, и освобождает капитал из вяло-плюсовых позиций. Не путать с trailing take: тот существует только ради выстрелов и к рядовым сделкам не прикасается; граница территорий — `arm` трейлинг-тейка.

**Семантика — киллер отстающих с грейсом от пересечения нуля:**

```
закрыть, если pnl > 0  И  (t − t_cross) ≥ G  И  mfe(t) < lock(t)
   где t_cross — первая минута, когда pnl стал > 0
```

Позиция в плюсе, но её лучший показанный результат ниже темпа, который к этой минуте уже показывали будущие победители, — статистически она мертва, капитал освобождается под следующий сигнал.

**Зачем грейс G — это структурное свойство киллера, а не нюанс**: любой победитель, восстанавливающийся из минуса, пересекает ноль с бегущим пиком ≈ 0 — заведомо ниже любого положительного `lock(t)` — и без грейса казнится на первой же положительной минуте. Траектории «ранний провал → позднее восстановление» у сигнальных каналов — существенная доля победителей, поэтому киллер без грейса предсказуемо проваливает допуск, а с ним рушится и верхняя губа анти-лимба (раздел 5). Грейс входит в пространство калибровки ЗАРАНЕЕ, со своим правилом фита, — не как «возможное расширение» после провала.

Сознательно отвергнутая альтернатива — **армированный рэтчет** (закрытие только при `peak ≥ lock && pnl < lock`): это другой механизм с другой экономикой — защита уже показанной прибыли. Он не прикасается к позиции, которая никогда не разгонялась, а значит не закрывает вялый плюс и оставляет анти-лимб без верхней губы; защита показанной прибыли — территория trailing take, дублировать её локом незачем. Армирование как защита от ложных срабатываний на скачке порога не требуется: семья кривых непрерывна, ступенчатых скачков нет.

Параметры и их судьбы (дисциплина «один реплейный кноб на кривую» сохранена):

- **Семья** `lock(t) = c·(1 − e^(−t/κ))`, монотонно растёт от нуля; действует с минуты армирования, вычисляемой правилом из раздела 1 (KS по MFE выше критического значения уровня α на k минутах подряд); до неё `Level.match → null`, листенер молчит.
- **κ — заморожен фитом формы** (63.2%-правило по эмпирическому q25 MFE(t) победителей, как τ у пола).
- **G — заморожен фитом распределения догона**: по победителям, пересекавшим ноль, считается время догона в ЦЕЛЫХ минутах — `t_cross` = первая целая минута с pnl > 0, догон = (первая целая минута, где mfe достигает эмпирической q25-кривой) − t_cross; G = q75 этого распределения (квантиль — константа процедуры, в паспорт). Целочисленная конвенция обязана совпадать у фита, реплея и листенера — дробные пересечения не используются нигде. Смысл: измеренное время, за которое реальные восстановления выходят на темп живых.
- **c — единственный реплейный кноб**: полная бисекция к границе `sup{c : вред ≤ цель}` (вред — победители, закрытые ниже своего финала), как у пола.
- **Критерий допуска лока — отдельный**: вред ≤ цели И дельта ≥ 0 (неотрицательная). Потраекторный реплей не ценит главный вклад лока — освобождение слота символа под следующий сигнал (перекрывающиеся сигналы глотаются, раздел 2): позиция, закрытая по своей же финальной цене на час раньше, даёт дельту 0, но возвращает слот. Полная денежная оценка лока возможна только многосигнальным реплеем; до него лок допускается как «неубыточный освободитель капитала».
- Режимные варианты допустимы (процедура допуска — раздел 6).

### 4.4 Trailing take

**Роль: ловить ВЫСТРЕЛЫ pnl** — редкие большие ходы (пики порядка +8% и выше, единицы траекторий на ансамбль), чтобы коллапс с пика не вернул выстрел в рядовую сделку. Рядовую доходность не собирает; до `arm` обязан молчать, иначе конкурирует с локом за одни сделки и атрибуция вкладов разваливается.

- Из траекторий победителей: распределение откатов от бегущего пика (`mfe[t] − pnl[t]`), разделённое на **пережитые** (после них `mfe` позже обновлялся — ход продолжился) и **терминальные** (после финального пика). `arm` — порог пиков «раннеров»; `retrace` — чуть глубже максимального пережитого отката раннеров.
- **Только глобальный**: раннеров единицы на весь год; любой режимный фит по хвостам — шум от одного экстремума. Значения сопровождать bootstrap-CI.
- `retrace` в нетто-пп, с зафиксированным свойством: фиксированные пп относительно жёстче на больших пиках (5пп от пика 25% — отдать 20% хода; от пика 8% — 62%). Если распределение откатов растёт с высотой пика — перейти на доли пика И в листенере сравнивать в долях; единицы не смешивать.

### 4.5 Валидация (допуск любой кривой в прод)

1. **Касательный реплей** на траекториях: сколько победителей убито, дельта суммарного нетто-pnl против бейзлайна «держать 24ч», срабатывания по механизмам. Обрезанные траектории включены в оба плеча.
2. **Блочный bootstrap-CI всего конвейера, блок = месяц**: ресемпл 12 месячных блоков с возвращением → рефит кривых → реплей; критерий допуска механизма — доверительный интервал дельты против бейзлайна НЕ включает ноль. Точечная дельта на десятках траекторий неотличима от удачи. Ресемпл отдельных траекторий запрещён по той же причине, по которой отвергнут leave-one-trajectory-out (раздел 6): траектории внутри месяца коррелированы, по-траекторный ресемпл протаскивает соседей в каждую псевдовыборку и занижает ширину CI.
3. **Walk-forward**: фит на одних месяцах, реплей на отложенных (единица разбиения — месяц, раздел 6). Дрейф формы кривой между окнами = нестационарность → упрощать семью, а не добавлять параметры.
4. **Механизмы включаются по одному** с замером вклада каждого; затем полный стек.
5. **Сверка реплея с листенерами**: бэктест strategy-файла одного месяца обязан воспроизвести закрытия оффлайн-реплея (те же сигналы, минуты, механизмы в нотификациях). Реплей и листенеры — две реализации одной логики; расхождение = баг в одной из них, и без этой сверки числа реплея ничего не говорят о проде.

## 5. Strategy-файл: исполнение сеток

### Сгенерированные сетки → Level

**Ни одно число не пишется руками** — только выход компилятора раздела 4, прошедший допуск 4.5; ручные значения — это заглушки, которые молча становятся продом. Шаг сетки — 1 минута, 1440 ключей на механизм: lookup у `Level` бесплатный, листенер тикает раз в минуту, укрупнение только теряет форму кривой. Читаемость диффа обеспечивает паспорт в шапке сгенерированного модуля, не укрупнение ступеней.

```typescript
// levels.gen.ts — СГЕНЕРИРОВАНО; руками не редактировать, при рефите перегенерируется.
// pnl_floor: floor(t)=a−b·e^(−t/τ), a=-1.1 b=3.4 τ=310мин; якорь floor(0)=hardStop=-4.5;
//   целевая путевая доля убитых победителей 5%, факт по реплею 4.6% [CI 2.1..7.8], n=187, период=2026
export const PNL_FLOOR_GRID: Record<number, number> = {
  0: -4.5, 1: -4.49, /* ... каждая минута ... */ 1439: -1.1,
};
// profit_lock (киллер отстающих): lock(t)=c·(1−e^(−t/κ)); армирование с минуты 142
//   (минута устойчивого KS-разделения по MFE); ключей меньше 142 нет — до неё лок молчит
export const PROFIT_LOCK_GRID: Record<number, number> = {
  142: 0.38, 143: 0.39, /* ... каждая минута ... */ 1439: 2.0,
};
// lock_grace: G = q75 времени догона эмпирической q25-кривой от пересечения нуля,
//   целые минуты (фит-правило 4.3; вычислено, не задано руками)
export const LOCK_GRACE_MINUTES = 480;
```

```typescript
// main.strategy.ts
import { Level } from "backtest-kit";
import { PNL_FLOOR_GRID, PROFIT_LOCK_GRID } from "./levels.gen";

const PNL_FLOOR_LEVEL = new Level(PNL_FLOOR_GRID);     // значение на минуте 0 = hard stop (4.1)
const PROFIT_LOCK_LEVEL = new Level(PROFIT_LOCK_GRID);
```

Семантика `Level`: значение наибольшего ключа `<= возраста`; после последнего ключа — последнее значение бессрочно; до минимального ключа — `null` (лок до минуты армирования молчит штатно).

### Листенеры

`listenActivePing` тикает каждую минуту, пока позиция открыта, — та же дискретизация, на которой калиброваны кривые. Возраст — только `getPositionActiveMinutes` (минуты от открытия по логическому времени). Сравнения — только `data.pnl.pnlPercentage` против сеток: нетто против нетто.

```typescript
import { commitClosePending, commitSignalNotify, getPositionActiveMinutes, listenActivePing, State } from "backtest-kit";

// Пол (4.2): рядовые лоси + анти-лимб снизу
listenActivePing(async ({ symbol, data }) => {
  const minutesActive = await getPositionActiveMinutes(symbol);
  const floor = PNL_FLOOR_LEVEL.match(minutesActive);
  if (floor === null) return;
  if (data.pnl.pnlPercentage > floor) return;
  await commitSignalNotify(symbol, { notificationNote: "pnl_floor: закрытие по полу" });
  await commitClosePending(symbol);
});

// Профит-лок (4.3): киллер отстающих с грейсом G от пересечения нуля.
// Бегущий пик НЕ копим сами: data.peakProfit — движковый running max (тот же, что
// peakProfitPercentage в дампе), по которому калибровались кривые (Приложение C.4).
// А вот минуту первого пересечения нуля движок НЕ отдаёт — для неё нужен State.
import { LOCK_GRACE_MINUTES } from "./levels.gen"; // G — выход компилятора, не ручное число
const CROSS_STATE = new State({ initialData: { crossMinute: null }, name: "lock_cross_state" });

listenActivePing(async ({ symbol, data }) => {
  const minutesActive = await getPositionActiveMinutes(symbol);
  const pnl = data.pnl.pnlPercentage;
  const { crossMinute } = await CROSS_STATE.getState();
  if (crossMinute === null && pnl > 0) {
    await CROSS_STATE.setState({ crossMinute: minutesActive }); // первая положительная минута
    return;
  }
  const lockLevel = PROFIT_LOCK_LEVEL.match(minutesActive);
  if (lockLevel === null) return;                  // до минуты армирования
  if (crossMinute === null || minutesActive - crossMinute < LOCK_GRACE_MINUTES) return; // грейс
  if (pnl > 0 && data.peakProfit.pnlPercentage < lockLevel) {
    await commitSignalNotify(symbol, { notificationNote: "profit_lock: отстал от темпа победителей" });
    await commitClosePending(symbol);
  }
});

// Трейлинг-тейк (4.4): пик тоже из data.peakProfit — закрытие при
// data.peakProfit.pnlPercentage >= TRAILING_ARM
//   && data.pnl.pnlPercentage <= data.peakProfit.pnlPercentage - TRAILING_RETRACE
```

Детали:

- `match(minutesActive)` дешевле `getValue()`: не ходит за ценой и pending-сигналом (они уже в аргументах листенера).
- Бегущие пик/просадку даёт движок (`data.peakProfit` / `data.maxDrawdown`, `IPublicSignalRow`) — собственный `State` для них не нужен и опасен рассинхроном (Приложение C.4). `State` нужен только для минуты первого пересечения нуля (грейс лока) — её движок не отдаёт; реплей обязан вычислять `t_cross` тем же правилом «первая минута pnl > 0».
- Каждое закрытие — с `commitSignalNotify`, где назван механизм: `closeReason` у всех `"closed"`, атрибуция возможна только по нотификации.

### Вход в проде

Тот же пайплайн, что в тесте (кеш/свежесть/гейты прода), плюс:

- `Position.moonbag` со страховочным стопом глубже hard stop на запас издержек и гэпа;
- `minuteEstimatedTime: 24 * 60` — терминальный выход на горизонте, за которым кривые не определены.

**Гарантия «не ждать худшего случая вечно»** — трёхслойная, и у каждого слоя своя полоса pnl:

1. `minuteEstimatedTime: 24 * 60` — терминальный выход движка при любом pnl; это механизм фреймворка, не листенер — не может не сработать из-за бага в сетке.
2. Пол (4.2): полоса `pnl ≤ floor(t)` — глубокий минус не пересиживает сужающийся допуск.
3. Лок-киллер (4.3): полоса `pnl > 0` при отставании от темпа — верхняя губа работает именно потому, что выбрана семантика киллера: рэтчет не тронул бы позицию, никогда не достигавшую порога.

**Полоса `floor(t) < pnl ≤ 0` (поздним возрастом примерно −1…0) не покрыта ни полом, ни локом** — позиция, болтающаяся на −0.5% весь день, доживает до терминального выхода. Это осознанный выбор, а не дыра: закрыть зазор можно было бы условием лока `pnl > floor(∞)` вместо `pnl > 0`, но тогда лок закрывал бы позиции в минусе — залез бы на территорию лосей и смешал роли механизмов. Максимальная жизнь в этой полосе ограничена слоем 1: ровно 24 часа, дольше худший случай не ждётся.

## 6. Годовой контур: 12 месяцев и режимные калибровки

Кривые честны внутри режима рынка и врут на его границе. Год данных позволяет калибровать по режимам — но только те механизмы, чья статистика выдерживает режимные n.

### Структура

- **12 пар файлов** — на каждый месяц свой `main.test.ts` (сборщик траекторий, фрейм месяца) и свой `main.strategy.ts` (реплей с уровнями), каждый месяц в СВОЕЙ папке (см. операционные требования: дампы перетираются).
- **Общий `config/levels.ts`** — один сгенерированный модуль, импортируемый всеми стратегиями. Экспортные группы:

```typescript
// config/levels.ts — СГЕНЕРИРОВАНО; паспорт каждой сетки в комментарии над ней
export const REGIME_THRESHOLDS = { /* пороги классификатора + ε буферной зоны */ };

// режимные: только пол и лок (центральные статистики, n работает)
export const BULLISH_PNL_FLOOR_GRID: Record<number, number> = { /* 1440 ключей */ };
export const BULLISH_PROFIT_LOCK_GRID: Record<number, number> = { /* ... */ };
export const SIDEWAYS_PNL_FLOOR_GRID = { /* ... */ };
export const BEARISH_PNL_FLOOR_GRID = { /* ... */ };
export const NEUTRAL_PNL_FLOOR_GRID = { /* ... */ };   // глобальный фит — фолбэк

// глобальные для всех режимов: хвостовые статистики на режимных n не оцениваются
export const HARD_STOP: number = /* ... */;
export const TRAILING_ARM: number = /* ... */;
export const TRAILING_RETRACE: number = /* ... */;
```

**Режимность — только у пола и лока.** Hard stop и trailing take всегда глобальные: hard stop — хвост q95+ (на 25–40 победителях режима это 1–2 порядковые статистики), trailing take — параметры по 3–4 раннерам года (режимный разрез хвоста — шум от одного экстремума).

### Каузальная разметка траекторий

Режимная метка присваивается **каждой траектории в момент её входа**, тем же правилом, каким прод-классификатор работает в рантайме: trailing-окно по свечам ДО момента входа. Месячной разметки («весь месяц бычий») не существует — у неё два дефекта: граница месяца условна, и разметка месяца его же свечами создаёт разрыв между тем, на чём учились кривые, и тем, что классификатор выберет в проде. При каузальной пометке каждой траектории обучающие пулы и продовый классификатор совпадают по построению — проверка «оракул против каузальности» становится тождеством и исчезает из плана.

Единица кросс-валидации при этом остаётся **месячным блоком**: траектории внутри месяца коррелированы по времени (соседние сделки, общий рынок), leave-one-trajectory-out дал бы утечку через соседей.

### Каузальный классификатор режима (обязателен для прода)

В live нет «файла месяца» с меткой — режим обязан вычисляться стратегией. Инструмент — `getCandles()`: отдаёт последние свечи до логического `when`, look-ahead в бэктесте невозможен по построению.

- **Данные**: `getCandles("BTCUSDT", "1d", 30)` — 30 дневных свечей BTC как прокси рынка (альты ходят по его бете); дневки устойчивы к микроструктурному шуму.
- **Две метрики, не больше**: тренд = 30-дневный ретёрн `close[29]/close[0] − 1`; вола = std дневных лог-ретёрнов за те же 30 дней.
- **Правило**: |тренд| ниже порога → SIDEWAYS, выше — BULLISH/BEARISH по знаку. Пороги — квантили метрик по году калибровки, скомпилированы в `REGIME_THRESHOLDS`; классификатор прода и разметка траекторий при фите используют ОДНО правило и ОДНИ пороги (иначе кривые откалиброваны для одних границ режима, а применяются в других). Пороги по 12 месяцам — грубая статистика, поэтому буферная зона ±ε обязательна, ε — тоже из распределения.
- **Выход в `NEUTRAL_`**: метрики в буферной зоне порога, либо режим не допущен (мало траекторий / провалил сравнение с NEUTRAL, см. ниже).
- **Режим фиксируется в момент входа на всю жизнь позиции**: классификатор зовётся один раз в `getSignal`, выбор кладётся в `payload`, листенеры читают оттуда. Переключение кривых посреди позиции запрещено — в проде исполнялась бы последовательность кусков кривых, которой нет ни в одном фите и которую нельзя проверить реплеем.
- **Атрибуция**: режим и значения метрик пишутся в `note`/`payload` — реплей и анализ дампа режут результаты по режимам.

### Как считается NEUTRAL_

`NEUTRAL_` — тот же конвейер раздела 4, применённый к объединённому ансамблю всех траекторий года без разреза по режимам. Никакой отдельной математики: та же семья кривых, те же целевые путевые доли, та же валидация. Известное свойство: хвосты объединённого ансамбля доминируются траекториями волатильных периодов, поэтому `NEUTRAL_`-пол смещён в мягкую сторону. Смещение безопасно по направлению: в тихом режиме мягкий пол почти не срабатывает и поведение сходится к бейзлайну — фолбэк теряет эффективность (меньше экономит на лосях), но не генерирует убыток; опасный режим отказа (слишком жёсткий для текущего рынка пол) исключён самим смещением.

### Как считаются BULLISH_ / BEARISH_ / SIDEWAYS_ (пол и лок)

Отличие от `NEUTRAL_` ровно одно — состав ансамбля: траектории с соответствующей каузальной меткой. Конвейер, семьи кривых и целевые доли — те же.

**Допуск режима — сравнением с честным NEUTRAL:**

1. Leave-one-month-out: режимная кривая фитится на траекториях режима БЕЗ одного месяца, реплей на исключённом месяце.
2. На том же исключённом месяце реплеится `NEUTRAL_`, **рефитнутый на тех же 11 месяцах** — NEUTRAL, видевший тестовый месяц, нечестен: утечка смещает сравнение в пользу фолбэка.
3. Критерий допуска: режимная кривая не хуже NEUTRAL на исключённых месяцах, с bootstrap-CI (4.5), а не точечной дельтой.
4. Режим, проваливший критерий или не имеющий месяцев для самой процедуры (один-два), не публикуется — классификатор для него уходит в `NEUTRAL_`. Порог «достаточно данных» вычислен процедурой, а не задан руками.
5. Ожидаемая асимметрия: в бычий год BEARISH почти наверняка выбывает — это честное отражение данных, не дефект; режимные кривые появляются по мере накопления месяцев каждого режима.

### Операционные требования 12 прогонов (пропуск любого = молчаливая потеря данных)

1. **`SYMBOL_LIST` на каждый месяц.** Бэктест запускается по символам из списка: сигнал по монете вне списка НЕ откроет позицию и траектории не даст — тихо, без ошибки. Перед прогоном месяца — скан постов канала, монеты месяца → в `SYMBOL_LIST`; после прогона сверка: число `opened` в дампе ≈ числу сигналов скана (минус перекрытия), расхождение = потерянные монеты.
2. **Фрейм на каждый месяц.** Смена периода = новое `frameName` в модуле бэктеста (лоадер берёт первую зарегистрированную схему фрейма). Свечи месяца докачивает `--cache`.
3. **Край фрейма.** Сигналы последних 24 часов месяца дают обрезанные траектории (~3% выборки); лечится фреймом месяц + 1 день.
4. **Дисциплина LLM-кеша.** Все 12 тестов делят один бакет прода (ключи `SYMBOL_timestamp` между месяцами не пересекаются); месяцы, которые прод не гонял, потратят LLM один раз. Смена промпта/схемы между прогонами = новое имя кеша, иначе смешаются ответы разных версий.
5. **Дампы перетираются каждым прогоном.** `dump/` пересоздаётся при запуске — каждый месяц живёт в своей папке со своим `dump/`, компилятор читает 12 дампов по папкам. Два месяца из одной папки = второй прогон молча уничтожает траектории первого; перед перепрогоном месяца убедиться, что компилятор данные уже забрал.
6. **Свечи для классификатора.** В первый день фрейма классификатору нужны дневки BTC за 30 дней ДО начала месяца — `--cache` их не прогревает (качает только фрейм по `SYMBOL_LIST`), `getCandles("BTCUSDT","1d",30)` сходит за ними в сеть. Проверить доступность при первом прогоне; BTCUSDT в `SYMBOL_LIST` для этого не нужен.

## 7. Зафиксированные решения

1. **Все пороги — в нетто-pnl.** Калибровка и исполнение в одной системе координат (`data.pnl` дампа = `data.pnl.pnlPercentage` листенера); от цен ничего не пересчитывается.
2. **Ручка каждого механизма — целевая путевая доля убитых победителей**, калибруемая касательным реплеем; поминутные квантили — только инициализация формы кривой.
3. **Profit lock = киллер отстающих с грейсом G от пересечения нуля**, не армированный рэтчет: рэтчет — другой механизм (защита показанной прибыли, территория trailing take), не закрывающий вялый плюс и оставляющий анти-лимб без верхней губы. Грейс — в пространстве калибровки с самого начала (киллер без него структурно казнит поздние восстановления на первой положительной минуте и предсказуемо проваливает допуск); допуск лока — по отдельному критерию «вред ≤ цели И дельта ≥ 0», его денежная ценность (освобождение слота символа) оценивается многосигнальным реплеем.
4. **Жёсткий фолбэк, не усадка.** Смешивание `w·режимная + (1−w)·глобальная` отвергнуто: в проде работала бы кривая-смесь, которой нет ни в одном чистом фите и которую нельзя проверить реплеем по отдельности. В рантайме всегда исполняется ровно одна целиком видимая кривая: режимная или `NEUTRAL_`.
5. **Режимность — только пол и лок.** Hard stop и trailing take глобальные: хвостовые статистики на режимных n не оцениваются.
6. **Режим фиксируется на входе** на всю жизнь позиции; переключение кривых посреди позиции запрещено (непроверяемая реплеем склейка).
7. **Входы автора не фильтруем.** Если сигналы канала убыточны (лонги в медвежий месяц без отскока) — мы не строим режимные гейты на вход: это означало бы взять на себя ответственность за торговые рекомендации. Канал с убыточными входами выбывает, подключается другой автор. Наша зона ответственности — точный парсинг руководства и качество исполнения/сопровождения; качество рекомендаций — зона ответственности автора.
8. **Ни одно число не пишется в сетки руками** — только выход компилятора с паспортом (семья, параметры, целевая доля, факт по реплею с CI, n, период).

## 8. ГИПОТЕЗА: источник эджа — сами подписчики

Автор вещает на широкую публику, поэтому вероятный источник эджа — не информация в сигнале, а **поток его собственной аудитории**, исполняющей уровни из поста. Публикация уровня сама создаёт уровень: самосбывающееся пророчество, тот же механизм, по которому работают круглые числа и фибо-уровни — на них смотрят все.

### Что уже подтверждено собственными данными

Event study по каналу-прототипу (crypto-yoda): зона входа «от-до» работает как стена из лимитников опоздавших подписчиков — цена, вернувшись в зону, встречает реальную поддержку. Уровень, созданный постом, существует физически независимо от того, был ли в нём изначальный смысл.

### Полная цепочка механизма

1. **Маркет-ордера в момент публикации** — толпа входит по рынку сразу после поста → импульсный толчок в направлении сигнала. Следствие, уже закреплённое в механике: эдж живёт возле момента публикации, 15-минутный гейт свежести — фронт-раннинг медленной части аудитории.
2. **Лимитники в зоне входа** — стена поддержки/сопротивления (подтверждено event study).
3. **Тейки толпы на целях автора** — на уровнях целей скапливаются встречные ордера, цена там буксует: цели автора — реальные точки сопротивления, созданные его же аудиторией.
4. **Масштаб эффекта обратен ликвидности монеты.** На BTC аудитория канала — капля в стакане; на мелких альтах поток десятков тысяч подписчиков с плечом — заметная доля объёма. Тяготение сигнальных каналов к мелким альтам не случайно: их собственная аудитория и есть движущая сила.

### Конкурирующие гипотезы (данными до конца не разделены)

- **Автор постит по уже идущему тренду** — эдж в тайминге тренда, толпа вторична.
- **Автор несёт реальную информацию** — поток толпы лишь ускоряет приход цены к справедливой.

Разделяются **пре-дрифт-анализом**: направленный ход ДО поста против хода ПОСЛЕ. Сильный пре-дрифт = «постит по тренду»; скачок только после публикации = информация появляется в момент поста. Пре-дрифт обязателен для каждого нового канала, прежде чем считать «эдж = толпа» доказанным.

### Проверяемые следствия (все тестируются по траекториям)

1. **Затухание по капиталу аудитории**: эдж исчерпывается по мере того, как аудитория довкладывается → естественный горизонт жизни позиции (12–24ч; отсюда `minuteEstimatedTime: 24 * 60`).
2. **Ход после поста растёт с падением ликвидности монеты** — прямой тест: величина MFE против среднего объёма торгов монеты.
3. **«92% accuracy» автора может быть арифметически честной без всякого скилла**: поток толпы сам дотаскивает цену до ближней цели — TP1 берётся почти всегда, маркетинг не врёт буквально. Правда вскрывается на дальних целях и стопах — ровно там, где живёт анализ траекторий.
4. **Хрупкость к аудитории**: канал, теряющий подписчиков, теряет источник движения. Следствие для мониторинга: наблюдать не только за дрейфом кривых (паспорта сеток), но и за активностью/ростом канала — падение вовлечённости предсказывает затухание эджа раньше, чем его покажет walk-forward.

### Статус

Доминирующая, частично подтверждённая гипотеза — НЕ установленный факт. Пре-дрифт-анализ на каждом новом канале — обязательный шаг онбординга; следствия 1–2 проверяются на годовом корпусе траекторий вместе с калибровкой сеток.

```js
export const T = 60; // прод: 1440; масштаб t_prod = 24 * t_toy

const seg = (pts) => (t) => { // кусочно-линейный путь по опорным точкам
```

```js
  for (const r of rows) {
    if (r.action === "opened") traj[r.signalId] = { pnl: [], mfe: [], mae: [] };

  }
  return traj;
}
```

### 0.3 Касательный реплей (ядро — написан один раз, используют все приложения)

Порядок проверок внутри минуты: пол → лок → трейлинг (конвенция; фиксируется и в листенерах). Метрика вреда едина для всех механизмов: **убитый победитель = победитель, закрытый механизмом с pnl ниже своего финального** (закрытие вялого плюса по его же финальной цене вредом не является — pnl тот же, капитал освобождён раньше).

```js
// appendix0.replay.mjs
// floorCurve: (t) => number | null
// lock: { curve: (t) => number | null, graceMinutes: number } | null  — грейс живёт В ЯДРЕ:
//   t_cross — первая ЦЕЛАЯ минута с pnl > 0; сама минута пересечения не судится
//   (только фиксирует t_cross, как и листенер); суд с t >= t_cross + graceMinutes.
// trailing: { arm, retrace } | null
export function replay(traj, { floorCurve = null, lock = null, trailing = null }) {
  const closures = [];
  let killedWinners = 0, winners = 0, stackSum = 0, baseSum = 0;
  for (const [signalId, tr] of Object.entries(traj)) {
    if (tr.winner) winners++;
    baseSum += tr.finalPnl;
    const last = tr.pnl.length - 1;
    let closed = null, peak = -Infinity, crossMinute = null;
    for (let t = 0; t <= last && !closed; t++) {
      const pnl = tr.pnl[t];
      peak = Math.max(peak, pnl);
      const floor = floorCurve && floorCurve(t);
      if (floor != null && pnl <= floor) { closed = { minute: t, mechanism: "floor", pnl }; break; }
      if (crossMinute === null && pnl > 0) {
        crossMinute = t;                         // минута пересечения: фиксируем, не судим
      } else if (lock && crossMinute !== null && t - crossMinute >= lock.graceMinutes) {
        const lockLevel = lock.curve(t);
        if (lockLevel != null && pnl > 0 && peak < lockLevel) {
          closed = { minute: t, mechanism: "lock", pnl }; break;
        }
      }
      if (trailing && peak >= trailing.arm && pnl <= peak - trailing.retrace) {
        closed = { minute: t, mechanism: "trailing", pnl }; break;
      }
    }
    if (!closed) closed = { minute: last, mechanism: "time", pnl: tr.pnl[last] };
    closures.push({ signalId, ...closed });
    stackSum += closed.pnl;
    if (tr.winner && closed.mechanism !== "time" && closed.pnl < tr.finalPnl) killedWinners++;
  }
  return {
    closures,
    killedWinnersShare: winners ? killedWinners / winners : 0,
    deltaVsBaseline: +(stackSum - baseSum).toFixed(2),
  };
}
```

**Ожидаемый выход без механизмов** (`replay(traj, {})`): все 9 закрыты `time`, `killedWinnersShare = 0`, `deltaVsBaseline = 0`, сумма стека = бейзлайн = 2.0+1.9+1.3+10.0+0.5−6.0−4.0−2.5−50.4 = **−47.2**.

**Ручная проверка**: сумма столбца finalPnl таблицы 0.2 = −47.2 ✓.

## Приложение A. Hard stop

### A.1 Инициализация: порядковая статистика при n=5

Финальные MAE победителей: W1 −0.4, W2 −1.6, W3 −0.5, R −0.4, S −0.4.

```js
import { rows } from "./appendix0.dataset.mjs";
import { groupDump } from "./appendix0.group.mjs";

const traj = groupDump(rows, 60);
const winners = Object.values(traj).filter((t) => t.winner);
const depths = winners.map((t) => -t.mae[t.mae.length - 1]).sort((a, b) => a - b);
// nearest-rank: при малых n интерполяции НЕТ, берётся порядковая статистика
const q = (p) => depths[Math.ceil(p * depths.length) - 1];
console.log(depths, "q95 =", q(0.95));
```

**Ожидаемый выход**: `depths = [0.4, 0.4, 0.4, 0.5, 1.6]`; `ceil(0.95·5) = 5` → пятая порядковая статистика → **q95 глубины = 1.6**, инициализация `hardStop₀ = −1.6`. При n=5 «q95» — это просто максимум: интерполяция не применяется, и это надо видеть глазами — одна новая траектория сдвинет значение.

### A.2 Петля калибровки: кноб → реплей → доля убитых → следующий кноб

Правило шага (константа процедуры, в паспорт): углублять на 0.25пп, пока путевая доля убитых победителей выше цели. Цель ≪1% при n=5 означает 0 из 5 (одна смерть = 20%).

```js
import { replay } from "./appendix0.replay.mjs";
let hardStop = -1.6;
for (;;) {
  const { killedWinnersShare } = replay(traj, { floorCurve: () => hardStop });
  console.log(hardStop, "→ killedWinnersShare =", killedWinnersShare);
  if (killedWinnersShare === 0) break;
  hardStop -= 0.25;
}
```

**Ожидаемый выход**:

| итерация | hardStop | убитые победители | доля |
|---|---|---|---|
| 1 | −1.60 | W2 (касание на t=10: pnl −1.6 ≤ −1.6, закрыт с −1.6 < финала +1.9) | 1/5 = 20% |
| 2 | −1.85 | никто (самый глубокий победитель W2: −1.6 > −1.85) | 0% → стоп |

Итог: **hardStop = −1.85**.

```js
const COST = 0.4, MARGIN = 1.25;

```

**Ручная проверка**: нетто-стоп −1.85 соответствует цене 100·(1+(−1.85+0.4)/100) = 98.55; страховка на 1.25пп глубже по цене: 98.55 − 1.25 = 97.30 ✓.

## Приложение B. Pnl floor

### B.1 Что заморожено, что крутится

Семья `floor(t) = a − b·e^(−t/τ)`, три параметра — три разные судьбы:

- **b — связан якорем**, не свободен: `floor(0) = a − b = hardStop` → `b = a − hardStop`;
- **τ — замораживается фитом формы** по эмпирическому q05 MAE(t) победителей (правило ниже), в реплейной петле не участвует;
- **a — единственный калибруемый параметр**, крутится реплеем.

### B.2 Фит τ по форме

Эмпирический q05 MAE(t) победителей (nearest-rank при n=5: `ceil(0.05·5)=1` → первая порядковая статистика MAE, то есть САМОЕ ОТРИЦАТЕЛЬНОЕ значение по ансамблю; в глубинах `−mae` это максимум) задаётся траекторией W2: глубина растёт от 0.4 (t=0) до 1.6 (t=10), дальше плоско. Правило фита (константа процедуры, в паспорт): **τ = первая минута, где глубина q05 проходит (1−1/e) ≈ 63.2% пути от стартовой к финальной глубине**, линейная интерполяция между тиками.

```js
// максимум глубин = q05 по MAE (внутренний Math.min — только кламп индекса)
const q05depth = (t) => Math.max(...winners.map((w) => -w.mae[Math.min(t, w.mae.length - 1)]));
const d0 = q05depth(0), dT = q05depth(60);
const target = d0 + (1 - Math.E ** -1) * (dT - d0);
let tau;
for (let t = 1; t <= 60; t++) {
  if (q05depth(t) >= target) {
    const prev = q05depth(t - 1);
    tau = t - 1 + (target - prev) / (q05depth(t) - prev);
    break;
  }
}
console.log({ d0, dT, target: +target.toFixed(4), tau: +tau.toFixed(1) });
```

**Ожидаемый выход**: `d0 = 0.4`, `dT = 1.6`, `target = 0.4 + 0.6321·1.2 = 1.1585`; глубина по W2 растёт на 0.12/мин: 0.4 + 0.12·t = 1.1585 → **τ = 6.3** (прод-масштаб: 6.3·24 ≈ 152 минуты).

**Ручная проверка**: q05depth(6) = 0.4+0.72 = 1.12 < 1.1585 ≤ 1.24 = q05depth(7); интерполяция 6 + (1.1585−1.12)/0.12 = 6.32 ✓.

### B.3 Петля калибровки a: бисекция до цели

Цель: путевая доля убитых победителей ≤ 5% (на toy это 0 из 5). Семантика ручки — **супремум допустимого a**: `sup{ a : доля ≤ цель }`. Поэтому бисекция ПОЛНАЯ, с обновлением обеих границ до сходимости — обрыв на первом допустимом a дал бы не границу, а артефакт пути деления (зависящий от стартового hi), оставляющий жёсткость пола на столе.

```js
const TAU = 6.3, HARD = -1.85, TARGET = 0.05, EPS = 0.01;
const mkFloor = (a) => (t) => a - (a - HARD) * Math.exp(-t / TAU);
let lo = HARD, hi = -0.4;      // lo — допустимое (const hardStop никого не убивает), hi — недопустимое
while (hi - lo > EPS) {
  const a = (lo + hi) / 2;
  const { killedWinnersShare } = replay(traj, { floorCurve: mkFloor(a) });
  if (killedWinnersShare <= TARGET) lo = a; else hi = a;
}
console.log("a =", +lo.toFixed(3)); // допустимая сторона границы с точностью EPS
```

**Ожидаемый выход**:

|---|---|---|---|---|

| 2 | −1.4875 | 20% (W2 на t=10: floor = −1.562 ≥ pnl −1.6) | жёстко | [−1.85, −1.4875] |

| 4 | −1.5781 | 0% (floor(10) = −1.634 < −1.6) | допустимо | [−1.5781, −1.4875] |

| … | ещё 3 шага (ширины 0.0453 → 0.0227 → 0.0113 → 0.0057; всего 8 итераций) | | | |hi − lo| < 0.01 |

Бисекция сошлась к −1.538 — допустимая сторона границы в пределах EPS ✓. ## Приложение C. Profit lock

### C.1 Минута армирования: KS по MFE на контрольных минутах

```js
const ks = (xs, ys) => {                      // двухвыборочная KS-дистанция
  const pts = [...xs, ...ys].sort((a, b) => a - b);
  let d = 0;
  for (const p of pts) {
    const fx = xs.filter((v) => v <= p).length / xs.length;
    const fy = ys.filter((v) => v <= p).length / ys.length;
    d = Math.max(d, Math.abs(fx - fy));
  }
  return d;
};
const CONTROL = [5, 10, 15, 20, 30, 45, 59];
const losers = Object.values(traj).filter((t) => !t.winner && !t.truncated);
for (const t of CONTROL) {
  console.log(t, +ks(winners.map((w) => w.mfe[t]), losers.map((l) => l.mfe[t])).toFixed(3));
}
```

**Ожидаемый выход**:

| t | 5 | 10 | 15 | 20 | 30 | 45 | 59 |
|---|---|---|---|---|---|---|---|
| KS | 0.267 | 0.267 | 0.267 | 0.267 | **0.467** | **0.667** | 0.800 |

Правило армирования: KS выше порога на k контрольных минутах подряд; **на toy k=2** — контрольных минут всего 7, с прод-значением k=3 из раздела 1 правило на такой сетке почти не срабатывало бы (демо-отступление помечено, в проде действует k=3). **Прод-порог — критическое значение двухвыборочного KS уровня α=0.05: `1.358·√((n+m)/(n·m))`; на toy (n=5, m=3) оно равно 0.991 и недостижимо в принципе** — поэтому на toy используется демонстрационный порог 0.45 (помечен как демо; в проде порог вычисляется из α и размеров выборок, руками не задаётся). Первая пара подряд ≥ 0.45 — минуты 30 и 45 → **минута армирования = 30**.

**Ручная проверка** (KS на t=30): MFE победителей {−0.4, −0.2, 0.5, 0.8, 10.0}, проигравших {−0.4, 0.6, −0.4}; в точке x=−0.4: F_побед = 1/5 = 0.2, F_проигр = 2/3 = 0.667 → разность 0.467 ✓.

### C.2 Семантика киллера против рэтчета (фиксация решения 3 раздела 7)

Иллюстративная кривая (до калибровки): `lock(t) = 1.5·(1 − e^(−(t−30)/20.4))` при t ≥ 30.

Траектория S (вялый плюс, mfe = pnl = 0.5 с t=15):

- t=38: lock = 1.5·(1 − e^(−8/20.4)) = 1.5·0.3244 = 0.487 < 0.5 → жива;
- t=39: lock = 1.5·(1 − e^(−9/20.4)) = 1.5·0.3567 = **0.535 > 0.5** и pnl 0.5 > 0 → **киллер закрывает S на t=39 с pnl +0.5** (= её финал, вреда нет, капитал освобождён раньше). Грейс условию не мешает: S пересекла ноль ещё на t=7, G давно истёк.

Армированный рэтчет (условие `peak ≥ lock && pnl < lock`) ту же S **не закрыл бы никогда**: на t=39 peak = 0.5 < lock = 0.535 — условие армирования ложно, и дальше lock только растёт. Одно это сравнение числами фиксирует, что киллер и рэтчет — разные механизмы.

### C.3 Фит κ и G, петля калибровки c

**Зачем грейс (демо структурного свойства)**: без G киллер казнит W2 на t=33 — его первой положительной минуте (pnl = mfe = +0.01, а любой положительный lock(33) выше) — и W3 на t=39 (+0.04). Порог выживания W2 без грейса: `lock(33) < 0.01 → c < 0.073`, при котором lock(59) = 0.053 < 0.5 = mfe S — лок, щадящий восстановления, бесполезен для вялого плюса. Это и есть тупик «казнь на пересечении нуля», который G устраняет.

- бисекция (та же схема, что B.3) → **c = 1.63**, допустимая сторона.

**Исходы при (c = 1.63, G = 20)**:

| W2 | жив: на t=53 mfe 1.41 ≥ lock(53) = 1.63·0.6761 = 1.102, дальше отрыв растёт | 0 |

## Приложение D. Trailing take

### D.1 Разбиение откатов на пережитые/терминальные

Правило: откат на минуте t (`mfe[t] − pnl[t]`) — **пережитый**, если ∃ t' > t: `mfe[t'] > mfe[t]` (пик позже обновился); иначе **терминальный**.

```js
const r = traj.R;
const last = r.pnl.length - 1;
const retr = [];
for (let t = 0; t <= last; t++) {
  const d = +(r.mfe[t] - r.pnl[t]).toFixed(2);
  if (d <= 0) continue;
  const survived = r.mfe.slice(t + 1).some((m) => m > r.mfe[t]);
  retr.push({ t, d, survived });
}
const maxSurv = Math.max(...retr.filter((x) => x.survived).map((x) => x.d));
const maxTerm = Math.max(...retr.filter((x) => !x.survived).map((x) => x.d));
console.log({ maxSurv, maxTerm });
```

**Ожидаемый выход**: пережитые откаты — минуты 21..41 (пик 10.0 обновляется на t=43..50 до 12.0), максимум **3.0 на t=30** (mfe 10.0, pnl 7.0); терминальные — минуты 51..60 (пик 12.0 больше не обновлялся), максимум **2.0 на t=60**. `{ maxSurv: 3, maxTerm: 2 }`.

**Ручная проверка**: на t=30 по опорным точкам pnl = 7.0, бегущий пик = 10.0 (взят на t=20) → откат 3.0; после t=42 pnl растёт выше 10.0 → пик обновился → откат пережитый ✓.

### D.2 Вычисление arm при n=5 победителях

Правило: раннеры = траектории с `mfe(финал) ≥ q90` (nearest-rank: `ceil(0.9·5) = 5` → пятая порядковая статистика). Пики финалов: {0.5, 1.3, 1.9, 2.0, 12.0} → q90 = 12.0 → **раннер один: R**. `arm` — середина зазора между минимальным пиком раннеров и максимальным пиком остальных: `(12.0 + 2.0)/2 =` **7.0**. При нуле раннеров в выборке механизм выключается (`arm = null`) — сравнивать не с чем.

### D.3 Retrace и правило отключения по CI

`retrace` = максимальный пережитый откат раннеров × **1.25** (коэффициент запаса — константа процедуры, в паспорт; не прилагательное «чуть глубже», а число): 3.0·1.25 = **3.75**.

Проверка реплеем на R: armed с t=15 — пик пересекает arm=7.0 при −0.4 + 0.52·t = 7 → t ≈ 14.2, и pnl(15) = 7.4 ≥ 7 (на t=14 пик 6.88 < 7); максимальный пережитый откат 3.0 < 3.75 → не срабатывает; терминальный 2.0 < 3.75 → не срабатывает → R доезжает до time-exit с +10.0. Механизм — чистая страховка, на toy не стреляет ни разу.

**CI при одном раннере**: блочный bootstrap (Приложение E) — раннер живёт только в блоке M2; вероятность ресемпла без M2 = (2/3)³ = 8/27 = **29.6%**. Правило компилятора: **если раннеры отсутствуют в ≥25% блочных ресемплов, либо CI retrace шире самого значения retrace — механизм публикуется ВЫКЛЮЧЕННЫМ** (`TRAILING_ARM = null`), с фактом в паспорте. На toy 29.6% ≥ 25% → **трейлинг-тейк на toy отключён**. Включённым он становится только на корпусе, где раннеры воспроизводятся в большинстве ресемплов.

**Ручная проверка**: (2/3)³ = 8/27 = 0.296 ✓.

## Приложение E. Валидация

Итоговая конфигурация на toy после приложений A–D: пол включён (a = −1.538, b = 0.312, τ = 6.3, якорь −1.85); лок включён (c = 1.63, κ = 20.4, G = 20, армирование t=30 — допущен по критерию «вред + неотрицательная дельта», C.3); трейлинг — `null` (отключён по CI-правилу, D.3). Все закрытия лока на toy происходят по финальным ценам жертв, поэтому на pnl-дельты реплея и ресемплов он не влияет — его вклад (слоты) виден только многосигнальному реплею.

### E.1 Блочный bootstrap и сборка CI

Ресемплятся **блоки-месяцы, не траектории** — по-траекторный ресемпл протаскивал бы коррелированных соседей месяца в каждую псевдовыборку и занижал ширину CI (тот же аргумент, которым отвергнут leave-one-trajectory-out).

```js
import { MONTHS, PATHS } from "./appendix0.dataset.mjs";

const blockIds = Object.keys(MONTHS);                   // ["M1","M2","M3"]
const resample = (rnd) =>
  Array.from({ length: blockIds.length }, () => blockIds[Math.floor(rnd() * blockIds.length)])
    .flatMap((m, i) => MONTHS[m].map((id) => [`${id}#${i}`, traj[id]])); // дубликаты различимы по суффиксу

const deltas = [];
for (let i = 0; i < 1000; i++) {
  const sample = Object.fromEntries(resample(Math.random));
  // fitPipeline — ПСЕВДОВЫЗОВ: композиция шагов приложений на переданном ансамбле:
  //   A.1-A.2 (init + петля hardStop) -> B.2-B.3 (фит tau, бисекция a)
  //   -> C.1, C.3 (армирование, фит kappa и G, бисекция c) -> D.2-D.3 (arm/retrace или null)
  // Возвращает { floorCurve, lock: { curve, graceMinutes } | null, trailing | null }.
  const curves = fitPipeline(sample);                   // кривые РЕФИТЯТСЯ на каждом ресемпле
  deltas.push(replay(sample, curves).deltaVsBaseline);
}
deltas.sort((a, b) => a - b);
console.log("CI95 =", [deltas[25], deltas[974]]);
```

**Один прогон руками, ресемпл [M2, M2, M3]** (траектории W2, L2, R ×2 + W3, L3, S):

- рефит hard stop: глубины финальных MAE шести победителей (W2×2, R×2, W3, S) = [0.4, 0.4, 0.4, 0.5, 1.6, 1.6], `ceil(0.95·6) = 6` → init −1.6 → петля A.2: −1.6 убивает W2×2 (2/6) → **−1.85**;
- рефит пола: связующая траектория та же (W2, касание на t=10) → a = −1.538, τ = 6.3 — кривая совпала с полной выборкой;
- реплей: полом убиты L2×2 (t=32, −1.6) и L3 (t=33, −1.555); лок (рефит κ/G/c на этом ресемпле опущен в деталях) закрывает S по её финальной цене — на дельту не влияет, в сумме учтён финалом; бейзлайн = 2·(1.9 − 4.0 + 10.0) + (1.3 − 2.5 + 0.5) = **15.1**; стек = 25.6 − 4.755 = **20.845**; **дельта = +5.75**.

**Второй ресемпл [M1, M1, M3]** — головой, без деталей: победители этого ресемпла (W1×2, W3, S) не ныряют глубже −0.5, поэтому рефит даёт ДРУГИЕ кривые (hardStop = −0.75; граница a упирается в плоскую −0.5 траектории W3 → a ≈ −0.51; τ ≈ 0.6) — bootstrap честно дрожит всем конвейером, не только реплеем; бейзлайн = −109.5 (две катастрофы C), стек = −0.74, **дельта = +108.8**.

Разброс дельт {+5.8 … +108.8} показывает, что CI на трёх блоках безразмерно широк и доминируется присутствием месяца с катастрофой — для toy это корректный вывод «данных мало», и ровно такого поведения от процедуры и требуется: точечная дельта +55.55 полной выборки сама по себе ничего не доказывает.

**Ручная проверка** (бейзлайн [M2,M2,M3]): (1.9 − 4.0 + 10.0) = 7.9; 7.9·2 + (1.3 − 2.5 + 0.5) = 15.8 − 0.7 = 15.1 ✓.

### E.2 Сверка реплей ↔ листенеры

Оффлайн-реплей (E.1, итоговая конфигурация) против бэктеста strategy-файла с теми же сетками: обе реализации обязаны дать идентичные закрытия. Механизм листенера читается из `notificationNote` (у всех `closeReason = "closed"`).

| signalId | реплей: минута / механизм / pnl | листенеры: минута / механизм / pnl | совпадение |
|---|---|---|---|
| C | 1 / floor / −2.40 | 1 / pnl_floor / −2.40 | ✓ |
| L1 | 7 / floor / −1.80 | 7 / pnl_floor / −1.80 | ✓ |
| L2 | 32 / floor / −1.60 | 32 / pnl_floor / −1.60 | ✓ |
| L3 | 33 / floor / −1.555 | 33 / pnl_floor / −1.555 | ✓ |
| W1 | 60 / time / +2.0 | 60 / time / +2.0 | ✓ |
| W2 | 60 / time / +1.9 | 60 / time / +1.9 | ✓ |
| W3 | 60 / time / +1.3 | 60 / time / +1.3 | ✓ |
| R | 60 / time / +10.0 | 60 / time / +10.0 | ✓ |
| S | 38 / lock / +0.5 | 38 / profit_lock / +0.5 | ✓ |

Известная гонка, помечаемая в паспорте: если листенерный механизм и `minuteEstimatedTime` срабатывают в одну и ту же минуту (последняя минута жизни позиции), порядок «пинг листенера против терминального закрытия движка» — свойство движка, не плана; pnl совпадает, но метка механизма может разойтись (time против profit_lock). Сверка обязана трактовать такое расхождение метки при равном pnl и минуте как совпадение.

**Ожидаемый выход**: 9/9 совпадений. Любое расхождение (минута, механизм или pnl) — баг в одной из двух реализаций одной логики; числа реплея до устранения расхождения о проде не говорят ничего.

**Ручная проверка**: суммы по столбцам закрытий совпадают со стеком E.1: 15.7 − (2.40 + 1.80 + 1.60 + 1.555) = 15.7 − 7.355 = 8.345 ✓.
