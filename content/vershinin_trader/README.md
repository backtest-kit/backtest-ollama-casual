# Стратегия vershinin_trader

LLM-стратегия для [backtest-kit](https://github.com/tripolskypetr/backtest-kit): читает закрытый Telegram-канал Вершинина (id `-1002833393903`) через `telegram-reader`, извлекает сигналы моделью `gemma4:31b-cloud` (structured output через [json-inference](https://github.com/tripolskypetr/json-inference), **с картинками** — сигналы часто идут графиком или карточкой позиции) и ведёт позицию по постам автора: он сам говорит, когда закрывать.

Формат канала принципиально отличается от crypto_yoda: нет диапазонов входа, нет сетки целей, нет стопов в постах. Автор входит «с текущих значений», направление и тикер часто видны только на картинке, а закрытие объявляется отдельным постом. Поэтому здесь **два независимых LLM-пайплайна**: поиск входа и поиск решения о закрытии.

## Файлы

| Файл | Назначение |
|---|---|
| `main.strategy.ts` | Стратегия: вход по посту, закрытие по посту, хард-стоп |
| `prompt_open.mustache` | Промпт поиска ВХОДА в позицию |
| `prompt_close.mustache` | Промпт поиска решения ЗАКРЫТЬ позицию |
| `session.txt` | MTProto-сессия Telegram (общая, скопирована из соседнего канала) |
| `assets/validate.mjs` | Регрессия промптов на живой модели (запускать после правок промптов) |
| `assets/read-posts.mjs` | Чтение текста постов канала |
| `assets/download-photos.mjs` | Скачивание фото постов — смотреть глазами перед правкой vision-правил |
| `dump/` | Отчёты бэктеста |

## Как работает

### 1. Поиск входа (`getOpenSignal`, кеш `vershinin_trader_open_v2`, интервал 4h)

На тиках без позиции (`listenIdlePing`):

1. Скрейпится окно 4 часа; посты без текста И без фото отбрасываются.
2. Все посты уходят модели одним запросом: текст с `ID`/датой/ссылкой + **картинка через `images`**, если есть. Фильтра по тикеру до LLM нет — тикеры в канале пишутся без `#` («BTC», «1000PEPE»), поэтому модель сама выбирает посты про `{{symbol}}` (промпт требует просмотреть ВСЕ сообщения).
3. Схема `PositionOpenFormat`: `id` поста, `symbol` (нормализованный `*USDT`), `position: long|short|wait`, `reasoning`.
4. Если модель вернула id, которого нет в окне, — сигнал отброшен.

Вход (`commitCreateSignal`): направление из поста, вход по рынку (`Position.moonbag` от текущей цены), **хард-стоп `HARD_STOP_PERCENT` (7.5%)** — свой, автор стопов не публикует. Id сигнала — `<postId>-<symbol>`, в `note` — сигнал, пост (без фото) и ссылка на него.

### 2. Закрытие по посту (`getCloseSignal`, кеш `vershinin_trader_close_v2`, интервал 4h)

На тиках с открытой позицией (`listenActivePing`) тот же пайплайн, но со схемой `PositionCloseFormat` (`action: hold|close`): модель ищет пост, где автор закрывает позицию по `{{symbol}}` **или все позиции разом** («мои шорты принимаю решение закрыть»). `close` → `commitClosePending`.

Частичная фиксация, перенос стопа, безубыток, аналитика — это `hold`, позиция не трогается.

### 3. Картинки — часть сигнала

Посты канала содержат три типа изображений, все уходят модели через `images`:

1. **График TradingView с position tool**: зелёная зона тейка / красная зона стопа; зелёная НАД входом = long, ПОД = short; тикер в шапке графика.
2. **Шер-карточка BYDFi**: тикер и «Лонг/Шорт» написаны текстом на карточке (оформление гуляет — светлое/тёмное).
3. **Скриншот панели позиции**: «BTCUSDT, Шорт | Кросс 100x», цена входа, P&L.

Критично (проверено на живых постах): **зелёный/красный цвет цифр P&L — это прибыль/убыток, а НЕ направление** — шорт в плюсе показывает зелёное число. Направление определяется только словом Лонг/Шорт или положением зон на графике. Это правило прописано в обоих промптах.

### 4. Логи (`Log.info`, человекочитаемый текст)

| Топик | Что пишется |
|---|---|
| `vershinin open` | окно пустое / отправлено N постов (M с фото) / вердикт модели с reasoning / кривой id отброшен |
| `vershinin close` | то же для пайплайна закрытия |
| `vershinin trade` | фактические действия: «открываю short от цены X по посту Y», «закрываю позицию по посту Z» |

Логи пайплайнов пишутся только при реальных вызовах (не из кеша) — раз в 4 часа на символ.

### 5. Константы

| Константа | Значение | Смысл |
|---|---|---|
| `WINDOW_MINUTES` | 240 | Окно скрейпа (тест; прод будет 15 минут) |
| `HARD_STOP_PERCENT` | 7.5 | Свой хард-стоп от цены входа — автор стопы не публикует |
| `interval: "4h"` (Cache) | 4 часа | Частота LLM-проверок (тестовый режим) |

## Формат постов канала

### Вход (position = long/short)

```
Работаю с ETH — в лонг с текущих значений, моя точка входа 2750$, цель ожидаю 2825$, стоп поставил 2715$, плечо 100х
```

```
Еще и 1000PEPE беру так же в лонг с текущих, на 3-4% вверх!
```

```
Работаю с SOL — в шорт
(+ карточка BYDFi: «SOLUSDT Бессрочный, Шорт | 50x»)
```

```
🤑ETH — можно рассмотреть кто без сделки.
(+ график с зоной тейка над входом = long)
```

Тикеры без пары и без `#`: «BTC», «ETH», «1000PEPE», «VIRTUAL» → `BTCUSDT`, `ETHUSDT`, `1000PEPEUSDT`, `VIRTUALUSDT`. Плечи автора (50x–100x) игнорируются.

### Закрытие (action = close)

```
❗️МОИ ШОРТЫ НА BYBIT ПРИНИМАЮ РЕШЕНИЕ ЗАКРЫТЬ, ПРИНЯТЬ УБЫТКИ И ДВИГАТЬСЯ ДАЛЬШЕ!
```

### Не сигнал (wait / hold)

- частичная фиксация и управление: «50% фиксанул, остальное в б/у», «стоп передвинул на 2705$»;
- аналитика и ожидания: «хочу увидеть снятие 5.3$», разборы рынка, «Мысли по BTC нужны?»;
- новости, реклама VIP-канала, #реклама, «пишите @alex_vershin»;
- посты без текста — продолжение альбома предыдущего.

## Валидация промптов

После любой правки `prompt_open.mustache` / `prompt_close.mustache`:

```bash
node assets/validate.mjs
```

10 кейсов на живой модели (входы текстом и картинкой, чужие монеты, отчёты, закрытия, управление позицией); exit-код 1 при провале. Кейсы привязаны к id постов — при устаревании обновить через `assets/read-posts.mjs`.

## Запуск

```bash
# бэктест (фрейм из modules/backtest.module.ts)
npm start -- --backtest --ui --entry ./content/vershinin_trader/main.strategy.ts

# то же с прогревом свечей (скачает свечи бэктеста, работает быстрее)
npm start -- --backtest --ui --entry ./content/vershinin_trader/main.strategy.ts --cache
```

Команду запускает сам пользователь (как и `signIn()` для Telegram).

Смена схемы LLM, промптов или логики отбора постов требует смены имён кешей (`vershinin_trader_open_v*` / `vershinin_trader_close_v*`) — иначе подмешаются старые закешированные ответы (текущие `_v2` — с картинками).
