# Стратегия crypto_yoda_channel

LLM-стратегия для [backtest-kit](https://github.com/tripolskypetr/backtest-kit): читает Telegram-канал `crypto_yoda_channel` через `telegram-reader`, извлекает торговые сигналы моделью `gemma4:31b-cloud` (structured output через [json-inference](https://github.com/tripolskypetr/json-inference)), входит только по свежим постам (не старше 15 минут) и сопровождает открытую позицию трейлингом по уровням тейк-профитов.

## Файлы

| Файл | Назначение |
|---|---|
| `main.strategy.ts` | Продовая стратегия: получение сигнала, вход по свежему посту, трейлинг уровней |
| `prompt.mustache` | Промпт для LLM: правила преобразования поста в JSON |
| `session.txt` | MTProto-сессия Telegram (создаётся `require("telegram-reader").signIn()`) |
| `dump/` | Отчёты бэктеста |

## Как работает

### 1. Получение сигнала (`getSignal`)

Обёрнуто в `Cache.file` (бакет `crypto_yoda_entry_v3`, интервал 5 минут — проверка канала каждые 5 минут на символ):

1. Скрейпит посты канала за последние 15 минут (`scrapeLookback`, окно `FRESH_WINDOW_MINUTES`, без look-ahead: пост, опубликованный позже текущего момента бэктеста, не виден). Старые посты в выборку не попадают вовсе, поэтому LLM зовётся только пока пост свежий.
2. Фильтрует посты по тегу монеты: для `BTCUSDT` ищется `#BTC` в тексте.
3. Если постов нет — `{ entry: null }`, LLM не вызывается.
4. Иначе посты уходят в `generateObject` (ollama, tool-вызов `provide_answer`): модель обязана вернуть объект по схеме `TradingPositionFormat`. Грамматика tool-вызова гарантирует структуру, рекурсивная валидация json-inference с ретраями — типы полей.
5. Из выборки достаётся пост-источник по `entry.id`; если модель указала id, которого нет в окне, сигнал отбрасывается. Возвращается `{ entry, message }`.

Схема ответа модели:

| Поле | Тип | Смысл |
|---|---|---|
| `id` | number | ID поста-источника сигнала, `-1` если сигнала нет |
| `symbol` | string | Тикер, нормализованный к `*USDT` (`#BTC/USDT` → `BTCUSDT`) |
| `position` | `long \| short \| wait` | `wait` — в постах нет входа (отчёты фильтруются) |
| `entryRange` | `{ from, to }` | Диапазон входа из поста |
| `targets` | number[] | Пять целей, строго числа (`items: number`) |
| `stoploss` | number | Хард-стоп |
| `reasoning` | string | Обоснование модели (для отладки, попадает в `note` сигнала) |

### 2. Условия входа (`getSignal` стратегии)

Вход отклоняется (`return null`), если:

- сигнала нет или `position === "wait"`;
- с публикации поста прошло больше 15 минут (`FRESH_WINDOW_MINUTES`; дата поста при чтении из кеша может быть строкой, поэтому сравнение через `new Date(message.date)`);
- нет третьей цели (`targets[2]`).

Гейта по цене нет: вход по рынку на любом свежем сигнале, независимо от положения цены относительно диапазона из поста. Event study показал, что сильнейшие сигналы (моментум) в зону входа не возвращаются, а «выгодные» входы глубоко в зоне статистически совпадают с пробоем стены лимитников.

При входе:

- **тейк-профит** ставится на самую дальнюю цель: `max(targets)` для лонга, `min(targets)` для шорта;
- **стоп-лосс** — из поста;
- все цели кладутся в `payload.levels` — их читает листенер сопровождения.

### 3. Трейлинг уровней (`listenActivePing`)

Идея — «level ratchet»: позиция едет до последней цели, но каждый взятый уровень становится полом.

- `getCurrentLevel` — сколько целей цена уже пересекла в свою сторону (для лонга `price >= level`, для шорта `price <= level`); номер уровня = счёт, с 1.
- Новый уровень взят → нотификация «Достигнут уровень N из 5» + запись в `LEVEL_STATE` (per-signal стейт backtest-kit, сбрасывается сам при закрытии сигнала).
- Уровни не взяты (`lastLevel === 0`) → рэтчет молчит, позиция живёт до стопа или тейка.
- Откат за взятый уровень: считается `drift` — на сколько цена ушла за уровень в неблагоприятную сторону (благоприятная сторона всегда даёт 0). Закрытие (`commitClosePending`) только при `drift > шаг_сетки × LEVEL_DRIFT_RATIO` (0.3), где шаг — расстояние до соседней цели (`getLevelStep`). Люфт адаптивен к плотности сетки: у PENGU шаги ~0.3–0.9%, у BTC — сотни долларов, допуск масштабируется сам.

### 4. Константы

| Константа | Значение | Смысл |
|---|---|---|
| `LEVEL_DRIFT_RATIO` | 0.3 | Люфт рэтчета, доля шага сетки целей |
| `FRESH_WINDOW_MINUTES` | 15 | Окно скрейпа и максимальный возраст поста для входа |
| `interval: "5m"` (Cache) | 5 минут | Частота проверки канала (и LLM-вызовов при наличии постов) на символ |

## Формат постов канала

### Сигнал (вход в позицию)

```
СИГНАЛ #BTC/USDT

📛 Риск сигнала: 6/10

🔑 Открыть ЛОНГ в диапазоне $78600 - $79400 - 6% депозита, плечо X15

🍒 Цели:

🔘 Закрыть по $80300
🔘 Закрыть по $80900
🔘 Закрыть по $82000
🔘 Закрыть по $83200
🔘 Закрыть по $84500

❗️ СТОП ЛОСС: $77400
```

Из него модель извлекает: `position` (ЛОНГ/ШОРТ), `entryRange` (диапазон), пять `targets`, `stoploss`. Направление целей: у лонга вверх, у шорта вниз — поэтому дальняя цель для лонга `max`, для шорта `min`.

### Отчёт о результате (фильтруется, вход не создаёт)

```
#PENGU/USDT
Тейк-профит 1 ✅
Тейк-профит 2 ✅
Тейк-профит 3 ✅
Тейк-профит 4 ✅

Прибыль: 53.2296% 📈
Период: 1 день 10 часов ⏰
```

Такие посты проходят фильтр по `#COIN`, но модель возвращает `position: "wait"` (промпт явно требует фильтровать публикации о результатах) — стратегия отвечает `null`. Шаблоны постов произвольные, общий вид сохраняется; рекламные вставки и аналитика без тикера отсекаются фильтром содержимого ещё до LLM.

## Запуск

```bash
npm start -- --entry --backtest --cache   # бэктест (фрейм из modules/backtest.module.ts) с прогревом свечей
npm start -- --entry --live               # live-режим
```

Смена схемы ответа LLM или логики отбора постов требует смены имени кеша (`name` в `Cache.file`) — иначе подмешаются закешированные ответы старой формы.
